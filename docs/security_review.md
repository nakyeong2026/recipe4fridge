# 배포 전 보안 점검 (6.4.13)

- 점검 기준: 태그 `PRD_08_01` 시점의 코드
- 스택: Streamlit + Streamlit Community Cloud + Supabase(Postgres) / 구글 로그인(`st.login`)
- 점검일: 2026-10-25
- 이 단계에서는 진단만 하고 코드는 고치지 않습니다.

상태: ☑ 구현 / △ 부분 / × 없음 / − 해당없음

| 항목 | 상태 | 위험도 | 근거와 수정 방향 |
|---|---|---|---|
| 01. CORS | ☑ | Low | 앱이 따로 API를 열지 않고, Streamlit 기본값 `server.enableCORS=true`를 그대로 씁니다. |
| 02. CSRF | ☑ | Low | Streamlit 기본값 `server.enableXsrfProtection=true`. 화면 조작은 웹소켓 세션 안에서만 일어납니다. |
| 03. XSS + CSP | △ | Med | AI가 만든 제목·조리 순서를 `st.markdown`으로 그립니다. HTML은 이스케이프되지만, 마크다운 링크와 외부 이미지는 그대로 그려지므로 모델이 넣은 외부 링크나 추적 이미지가 보일 수 있습니다. AI 출력은 마크다운 특수 문자를 이스케이프하거나 `st.text`로 그려야 합니다. CSP 헤더는 Streamlit Cloud에서 바꿀 수 없습니다. |
| 04. SSRF | − | − | 서버가 호출하는 주소는 OpenRouter의 고정 주소뿐이고, 사용자가 주소를 넣을 곳이 없습니다. |
| 05. AuthN/AuthZ | △ | Med | 비밀번호는 PBKDF2-SHA256(30만 회, 솔트)로 저장합니다. 구글 계정은 `google_sub`로만 찾아서, 같은 이메일의 비밀번호 계정과 자동으로 합치지 않습니다(수업 노트 시연에서 High였던 계정 탈취 경로를 막음). 남은 문제는 두 가지입니다. 가입할 때 이메일 인증이 없고, 로그인 실패 횟수 제한이 없어 비밀번호를 무작위로 대입할 수 있습니다. 실패 횟수 제한과 이메일 인증을 넣어야 합니다. |
| 06. RBAC · 테넌트 | ☑ | Low | 역할은 일반 사용자 하나입니다. 레시피 조회와 삭제 쿼리에 모두 `user_id` 조건이 붙어 있어 남의 레시피에 접근할 수 없습니다(시험 `test_save_list_delete_recipes`로 확인). |
| 07. 최소권한 | × | Med | 앱이 Supabase에 `postgres`(표 소유자) 계정으로 연결해서 모든 권한을 가집니다. 앱 전용 DB 역할을 만들어 두 표의 SELECT/INSERT/UPDATE/DELETE만 주는 것이 좋습니다. OpenRouter 키에는 사용 한도(50)가 걸려 있어 키가 새어도 피해 금액에 상한이 있습니다. |
| 08. Input + SQLi | △ | Low | 모든 SQL이 자리 표시자(`%s`) 바인딩이라 SQL 주입은 막혀 있습니다. 다만 표시 이름이나 재료 이름에 길이 제한이 없고, 업로드 크기가 기본 200MB입니다. `server.maxUploadSize`를 10MB 정도로 줄이고, 입력 길이 제한을 두는 것이 좋습니다(Pillow의 압축 폭탄 검사는 기본으로 켜져 있음). |
| 09. Rate Limit | × | **High** | 로그인하지 않아도 AI 호출을 무제한으로 누를 수 있습니다. 무료 호출은 계정 전체가 하루 50회를 함께 쓰므로, 한 사람이 반복해서 누르면 모든 사용자의 그날 인식과 레시피 생성이 막힙니다. AI 호출에 로그인을 요구하고, 사용자별 하루 호출 수를 DB에 세서 제한해야 합니다. |
| 10. 쿠키 · 세션 | ☑ | Low | 구글 로그인은 Streamlit이 `cookie_secret`으로 서명한 쿠키를 씁니다. 비밀번호 로그인 상태는 서버 메모리의 세션에만 있어 쿠키로 새지 않습니다(대신 새로 고침하면 다시 로그인해야 함). |
| 11. Secret · Rotation | △ | Low | 키는 `.env`(git 제외)와 Streamlit Secrets에만 두고, 화면과 로그에 출력하지 않으며, 커밋 전에 키 패턴을 검사합니다. 키가 새었을 때 바꾸는 순서(OpenRouter 키 폐기 → 새 키 발급 → `.env`와 Secrets 교체 → 앱 재부팅)가 문서로는 없습니다. |
| 12. HTTPS · 보안헤더 | △ | Low | Streamlit Cloud가 HTTPS를 제공합니다. HSTS, CSP 같은 응답 헤더는 플랫폼이 정해서 앱에서 바꿀 수 없습니다. |
| 13. Audit Log | × | Med | 로그인 실패, 가입, 레시피 삭제 같은 기록이 남지 않습니다. 계정 이상 행동을 나중에 확인할 수 없으므로, 최소한 로그인 실패와 삭제를 표에 남기는 것이 좋습니다. |
| 14. 에러 노출 | △ | Med | Streamlit 기본값 `client.showErrorDetails=full`이라 예상하지 못한 예외의 추적 정보가 사용자 화면에 나옵니다. DB 연결 실패 메시지(호스트 이름 등)도 사이드바에 그대로 보입니다. `.streamlit/config.toml`에 `showErrorDetails = "none"`을 넣고, DB 오류는 일반 문구로 바꿔 보여 줘야 합니다. |
| 15. 의존성 취약점 | ☑ | Low | `pip-audit -r requirements.txt` 결과 알려진 취약점이 없습니다(2026-10-25). 다만 버전을 `>=`로만 묶어 두어서, 배포할 때마다 다른 버전이 설치될 수 있습니다. |

## 우선 고칠 것
1. **09 Rate Limit (High)**: AI 호출에 로그인을 요구하고, 사용자별 하루 호출 수를 제한합니다.
2. **14 에러 노출 / 03 XSS**: `showErrorDetails = "none"`으로 바꾸고, AI 출력을 이스케이프해서 그립니다.
3. **05 로그인 실패 제한 / 07 최소권한 / 13 감사 기록**: 계정 보호와 사고 대응을 위한 작업입니다.

## 확인하지 못한 것
- Supabase 프로젝트를 아직 만들지 않아서, 실제 DB에서 RLS가 켜졌는지는 확인하지 못했습니다. 코드는 표를 만들 때 RLS를 켜도록 되어 있습니다. 연결한 뒤 Supabase 대시보드 → Security Advisor에서 `users`, `saved_recipes`에 RLS 경고가 없는지 확인해야 합니다.
- 배포한 앱의 실제 응답 헤더는 배포한 뒤에 확인해야 합니다.
